## 阶段 F：落地真实代码（2026-11-13，用户 m03145-3「界面展示到能展示的地步」）

问题（设计稿指出、代码确实存在）：`src/client/environment/maintenance/DiskUsageCard.tsx:207-227` 的「遗留数据」分组原本渲染在 `.diskUsageScroll` 列表**之外**、卡片 body 内；而 `.diskUsageCard` 是固定高度卡（`src/client/config-manager.module.css:3366-3395`，只有 `.diskUsageScroll` 自带滚动）—— 遗留目录条数一多，整块会被卡高裁掉。

改动：
1. `DiskUsageCard.tsx` 把 legacy 分组由裸 Fragment 换成 `<div className={css.planScroll + ' ' + css.duLegacyScroll}>`，组标题、口径说明、逐条「目录名 + mono 相对路径 + `size · files`」全部保留在容器内。
2. `config-manager.module.css` 在 `.duList` 之后新增 `.duLegacyScroll { max-height: 108px; overflow-y: auto; scrollbar-gutter: stable; }`（108px ≈ 组标题 + 3 行；`scrollbar-gutter` 防止滚动条出现时行宽跳动）。

未做（按「能展示的地步」界定）：没有把遗留条目并入主表合计（`src/core/disk-usage.ts:163-170` 明确 legacy 不计入 `totalBytes`，混进去会让合计失真）；没有为遗留目录提供删除入口（同一文件的 `LEGACY_DATA_DIRS` 注释：只报告、不代删）。

验证：`npm run typecheck` exit 0；`css-scale-guard` / `css-token-guard` 通过（新增类只动 `max-height` 与滚动，不引入字号/间距/圆角档位）；`npm test` 全绿；`npm run build` exit 0。**视觉未复拍 → NOT VERIFIED（视觉）**。
