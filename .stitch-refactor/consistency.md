## 审计口径（两条硬约束，避免假阳性）

1. **脚手架不算**：Stitch 每屏固定注入 `<script id="tailwind-config">`，Material 色阶（`001946 / 93000a / ffdad6 / ba1a1a …`）与 `.material-symbols-outlined{font-size:14px}` 只属于该脚本与图标字体规则，`<body>` 对这些色零引用。文本级全局扫描会得出「53 屏全部跑色」的错误结论。
2. **规范以源码为准，不以稿为准**：真实 `src/client/config-manager.module.css` 里 `.statusBar` 是 `height:28px; margin:0 8px 8px; border:1px solid; border-radius:var(--cm-r-3)` —— 内缩圆角盒是正确形状；`common/ConfirmDialog.tsx` 的 `Modal.Footer` 是「确认按钮在前、取消 ghost 在后」+ `flex-end` —— **确认/危险在左、取消在右**是正确次序。稿与源码冲突时判稿为偏差。

## 系统性问题（先看这三条，C 行的成因都在这里）

- **S-1 外壳规则（状态栏内缩）——浏览器实测，54/54 已合规**：判据 = 从「v0.8.0 · DSH 2.4」向上找最近的 28px 高元素，量宽度/圆角/左右留白/父容器溢出；真值 = 宽 546–548px、圆角 8px、左右各 8px、overflow 0。
  - 32 屏由 Stitch 出图即为内缩圆角盒；22 屏（D-05、D-06、D-07、D-08、D-09、D-14、D-14b、D-15、D-17、D-18、D-19、D-22、D-23、D-24、D-33、T-01、T-02b、T-02c、T-04、T-05、T-06、T-07）在 HTML 层补内联样式后达标，其 PNG 仍是 Stitch 原图（仅状态栏一处不同）。
  - 教训：三轮里出现的「53/53 全通栏」「44/55 合规」「31/55 合规」全部作废——前两者靠文本里有没有 rounded/border 字样判断，后者靠「最近 ≥300px 宽元素」判断（会把外层 wrapper 当成状态栏）。**唯一可信口径是长度受限的浏览器几何实测**。
- **S-1b 二次重画会被 Stitch 判重**：对已含内缩状态栏的屏再发「改状态栏」指令，Stitch 会答「该改造已在历史版本落地」并只回文本、不回新 screen（P-02、`0a8f79103b804750909c58d1500f363c` 实测）。要动这类屏必须换角度描述（如连带改内容）或 `generate_variants`，不能指望 edit_screens 重出图。
- **S-2 遮罩呈现三派**：真实底层页面 + 压暗（多数）、灰阶骨架条（8 屏）、完全无遮罩（D-26 旧版、D-20 旧版）。原因：压暗必须画成不透明灰底（Stitch 不认 rgba 遮罩），提示词里写「压暗」时它时而画骨架、时而忽略。
- **S-3 弹窗几何漂移**：`dialogCard` 实测 525–531px（应 600），`dialogWide` 541px（应 720 的 96% ≈ 691），遮罩强度 24% / 30% / 42% 三种。

## 总体结论

- 53 项全部出图（PNG + HTML + 提示词 + 页面记录），页面级 5 屏与流程面板 8 组的结构、字段、文案均对齐源码；色板/字号/圆角在 `<body>` 口径上合规。
- 遗留集中在两处系统性偏差：**外壳长尾（状态栏内缩、导航激活态）** 与 **弹窗遮罩/按钮族**。这两类靠逐屏重画 53 次性价比低，建议下一步只做「外壳模板固定件」：单独出一张外壳基准屏（含状态栏内缩、胶囊激活、四图标），其余屏以它为准局部对齐——这条建议留给阶段 F 决定。
- 已知限制：Stitch 不接受截图作为图片入参（只能文字化描述，故 `shots/*-before.png` 仅作对照）；常输出 2560×2048 横版，部分屏用 Pillow 按面板外接框裁切；`edit_screens` 偶发返回新 id 但截图字节不变（以 HTML 为准）。
