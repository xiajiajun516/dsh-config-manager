#### UI-01（high）结果报告与错误明细用 `pre`：长行不折行且被父容器裁掉；报告也**未按仓库纪律限高内滚**

- **现象**
  1. 导出/导入完成后，结果报告正文是一整块等宽文本。只要出现一条长行（导入失败原因、回滚项、警告文本，形如 `原因: …`），该行会横向溢出并被外层卡片**裁掉**：用户看不到内容，也无法横向滚过去看。
  2. 同一块报告没有最大高度：条目多时整页被撑长，必须靠整页滚动才能翻到底（违背「长报告限高内滚」）。
- **证据**
  - `src/client/common/ReportView.tsx:91`、`:104`、`:108` —— 三处都是 `<pre className={css.reportText}>`，而 `css.reportText` 只定义了字号与颜色。
  - `src/client/config-manager.module.css:2755-2758` —— `.reportText` 只有 `font-size` 与 `color`：**没有** `white-space`、**没有** `overflow-wrap`、**没有** `max-height`。
  - `src/client/config-manager.module.css:2742-2748` —— `.reportView { … overflow: hidden; }`：溢出的长行被直接裁掉（浏览器对 `pre` 的默认 `white-space: pre` + `overflow: visible`）。
  - 同因缺陷（建议一并修）：`src/client/common/ErrorBanner.tsx:40`、`:64` 也是 `<pre>`；`src/client/config-manager.module.css:2786-2789` 的 `.errorLine { overflow-wrap: anywhere }` 落在 `<pre>` 上**是无效声明**（`overflow-wrap` 仅在允许换行时生效）——看起来修过，实际没生效。
  - 复现步骤：导入一份含「插件安装失败」的备份（失败项 message 通常较长）→ 结果页报告中该行右侧内容不可见；或把窗口收窄到 <900px 再看报告。
  - 仓库已有同类结论与修法：`DESIGN.md:236-239`（`.conflictDetail`「不再用 `<pre>`：`white-space: pre` 会让长配置横向溢出」）；`AGENTS.md` §UI 硬性规则 8（长报告限高内滚 `reportScroll`）。
- **期望**
  1. 报告/错误明细改用普通块元素（或对 `<pre>` 显式 `white-space: pre-wrap; overflow-wrap: anywhere`），长行折行而不是被裁，与 `DESIGN.md:236-239` 的既有结论保持一致。
  2. 报告容器套用既有 `.reportScroll`（`src/client/config-manager.module.css:1243-1255`，`max-height: 380px`），落实 `AGENTS.md` 硬性规则 8 与 `DESIGN.md` §6「长列表/大报告限高内滚」。
- **涉及文件**：`src/client/common/ReportView.tsx`、`src/client/common/ErrorBanner.tsx`、`src/client/config-manager.module.css`

#### UI-06（high）密钥补录页：看到的值 ≠ 提交的值（返回再进入会清空显示，但旧值仍被提交）

- **现象**：在「补录密钥」页输入凭据后点「上一步」再回来，输入框全部为空，但上一次输入的值仍留在状态里，此时点「下一步」会把这些**看不见**的值提交。更严重的是：回到该页后编辑任一字段，会把其它 ref 的已填值从提交集合里**丢掉**（第二次编辑只保留当前这一个 ref）。
- **证据**
  - `src/client/import/ImportWizardView.tsx:86-91` —— `SecretsForm` 用 `useState<Record<string,string>>({})` 存本地输入，**没有**从 store 的 `imp.secretInputs` 回填初值。
  - `src/client/import/ImportWizardView.tsx:87-91` —— `setRef` 基于**当前本地 state** 做 `{ ...inputs, [ref]: value }`；本地 state 为空时，提交集合就被这一个 ref 覆盖。
  - `src/client/import/ImportWizardView.tsx:853-867` —— 该页只在 `phase === 'secrets'` 渲染；返回预览步即卸载组件（本地 state 随之丢失）。
  - `src/client/import/ImportWizardView.tsx:495-498` —— `finishSecrets` 提交的是 **store** 的 `secretInputs`（旧值），不是界面上显示的内容。
  - `src/client/run-store.ts` 的 sessionStorage 白名单刻意不持久化 `secretInputs`（安全设计，正确）；问题只在**同一次会话内的界面/提交不一致**。
  - 复现步骤：导入一份缺 2 个凭据的备份 → 密钥页填 A → 「上一步」→「下一步」回到密钥页（输入框为空）→ 填 B → 「下一步」→ 实际提交集合只含 B；或在空白输入框下直接「下一步」，实际提交的仍是 A。
- **期望**：表单状态与提交状态同源。最小改法二选一：① `SecretsForm` 接受 `initial={imp.secretInputs}` 并以它回填（受控），`setRef` 基于 store 最新值合并；② 离开该页时清空 store 的 `secretInputs`（使「界面空 = 提交空」）。无论哪种，必须保证「看到什么就提交什么」。
- **涉及文件**：`src/client/import/ImportWizardView.tsx`（必要时 `src/client/run-store.ts`）
