# 02 · 首页（home）内容清单

> 事实来源：`src/client/home/HomePanel.tsx`（1044 行）+`src/ui/overview-view.ts`。
> OpenDesign 只需要读「区块 / 数据 / 状态」，不需要知道 React 结构。

## 1 区块顺序（顺序本身是设计决定，不是随意排列）

| # | 区块 | 类名（现状） | 何时出现 | 为什么在这个位置 |
| --- | --- | --- | --- | --- |
| 0 | 读取失败横幅 | `.banner` | `loadError !== null` | 数据没拿到时，绿色的健康点是假的 ⇒ 必须压在最上面 |
| 1 | 状态条 | `.statStrip` | 恒在 | 一屏只回答一个问题：现在安全吗 |
| 2 | 动作工具栏 | `.toolRow` | 恒在 | 结论之后立刻给动作 |
| 3 | 最近活动卡 | `.activityCard` | `!emptyState` | 首页最后一个数据块，回答「刚才发生了什么」 |
| 3' | 首用三步 | `.emptySteps`（内嵌 Stepper） | `emptyState` | 替代 3 的位置；**不再重复放按钮** |

`emptyState` 判定：备份与快照都为空、且历史为空（新装机）。

## 2 状态条（`.statStrip`）

一条 28px 高的圆角条（`--cm-r-3`），左侧健康段，右侧指标段；`data-tone` = warn/error 时整条边框换色。

**健康段**（5 种取值，来自 `overviewHealth()` 的保守优先级）：

| kind | 文案 | 说明 |
| --- | --- | --- |
| error | 有未解决的恢复事项 | SAFE MODE 激活；此时健康段**本身是按钮**，点击直达备份页「事故恢复」 |
| warn | 尚无任何备份 | 备份与快照都为空 |
| warn | 上次定时备份失败 | schedule.enabled 且 lastRunStatus=failed |
| warn | 自动备份已关闭 | 已有备份但定时是关的（与指标自相矛盾的场景） |
| ok | 一切正常 | 其余 |

**指标段**（4 个，全部可点击，点击跳到对应页）：

| key | 标签 | 值形态 | 补充值 `dim` |
| --- | --- | --- | --- |
| backups | 备份 | 数字 | 最近一次备份的相对时间（如 `3 小时前`） |
| snapshots | 快照 | 数字 | 体积合计（未知则整段不出现） |
| schedule | 定时备份 | 「开启 / 关闭」 | 下次运行时间 |
| sync | 同步 | 状态词 | 远端设备名 |

三条硬规则：
1. **加载中 → 该段数值位置换骨架条**（宽度不变，数据到货只换值，不重排）。
2. **未知值不显示 0**；同步不可用时显示 `—` + 一句「同步不可用」，不写 0。
3. 健康点用 `StatusDot` 三态（ok/warn/error），只有 ok 是「降噪」的绿点，warn/error 必须同时有文字。

## 4 最近活动（`.activityCard`）

- 标题「最近活动」，右上**不带**「加载中…」字样（骨架即反馈）。
- 四列 grid：时间 / 事件 / 详情 / 结果。列头与数据行**共用同一 grid 与行高**（加载态也用同一行表头，数据到货是「占位换文字」）。
- 时间：相对时间（`3 分钟前`），title 给绝对时间。
- 事件：kind 文案（导入 / 恢复 / 回滚 / 备份 / 快照删除 / 同步应用…，未知 kind → 其他）。
- 详情：**中段省略**（`midEllipsis`），因为区分信息在尾部（文件名时间戳、项数）。
- 结果：成功 = 绿点 + 「成功」（降噪，不用徽章）；失败 / 跳过 / 进行中 = 徽章（必须被看见）。

状态矩阵：

| 状态 | 渲染 |
| --- | --- |
| 加载中 | 表头 + 5 行骨架（同几何） |
| 空 | 只有一行灰字「暂无操作记录」；**不渲表头** |
| 失败 / 无历史 | 一行灰字「活动记录不可用」；不渲表头 |
| 有数据 | 最多 8 行可视，其余 `.activityRows` 内滚（`max-height`），卡片高度随内容 |

## 5 首用三步（空态）

`Stepper` 三步：备份 → 导出 ZIP → 导入。第一步 `current`，其余 `todo`。放在一张 `.activityCard` 里，组标签「从这里开始」。

## 7 现状问题（本次要解决的，来自真机反馈与设计评审）

1. 四块之间靠留白分，纵向节奏平，扫视抓不到重点。
2. 状态条把「结论」与「四个指标」压成同权重。
3. 活动表事件列与详情列信息重复。
4. 数据少时页面塌成半屏，底部空带 >100px。
5. 主色分散：工具栏四个按钮里有多个接近主色的描边，一屏没有焦点。
