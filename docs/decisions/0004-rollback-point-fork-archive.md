# ADR-0004：对话回退 = fork + 归档，回滚点 = 内容寻址台账 + 两态采集

- 状态：已采纳（Accepted）
- 日期：2026-10-22（记录既有决策）

## 背景

「把对话退回上一轮」听起来像截断会话日志，但**运行中的 DSH 不会重读磁盘**：宿主内存里的活动会话保持不变，
平台也没有 drop/reload API（离开再回来、整页刷新都不重读）。所以「就地截断」在运行中的实例里根本不生效 —— 用户会看到「退回了但没变」。

同时，回退不只是对话：用户真正想要的是「这一回合改的文件也回去」。因此一个可用的回退点必须同时持有**工作区态**和**会话态**。

## 决策

1. 回退实现 = 用 `sessionController.fork` 从目标边界 fork 出新会话 + 归档原会话（A 无感替换）。**绝不直接 `SessionStore.fork`**（会跳过落盘与归位）。
2. 回滚点 = 工作区 + 会话两态；工作区态必须在 `turn/start` 拍（`turn/end` 只更新缺省边界）—— 在回合结束拍会固定成「改完之后」，用户会看到文件没被撤回。
3. 台账一条一写、载荷内容寻址、有字节预算；自动留点缺省关闭，关闭即解绑 `session/event` 订阅。
4. 删除集只有一份规划（`planCreatedRemovals`），预览与执行共用；判据是**能证明「留点时不存在」**，证明不了就 refused 且零删除。
5. 归位 cwd 多源 + 失败重试 + 失败写诊断；失败仍返回 childId 并附 warning，而不是静默成功。

## 后果

- 好：回退在运行中真的生效，且「文件回去了」与「对话回去了」一致。
- 坏：回退产生新会话，历史列表会多一条；必须靠归档与文案说清楚。
- 坏：两态采集比只读日志贵得多，需要并发 + 自适应预算 + 缺口优先（见 `docs/modules/recovery.md`）。

## 证据

- `src/core/rollback-point.ts`（两态采集、删除集规划、预算）
- `src/routes/recovery.ts`、`src/index.ts` 的恢复端点（走 `sessionController.fork`）
- `docs/lessons/recovery-console.md`（就地截断为何不可能、fork 归位细节、捕获约束）
