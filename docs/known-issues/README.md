# docs/known-issues/ — 限制、缺口与债

回答「**这能力能不能做 / 还欠什么**」。三份文档分工不同，别混：

| 文档 | 记什么 | 判据 |
|---|---|---|
| `known-limits.md` | 当前**做不到 / 做了会出事**的硬限制（平台与外部事实，仓内不可证） | 有外部事实或真机复现 |
| `known-gaps.md` | 已知**实现缺口**台账（不是路线图，也不是对外契约） | 只登记未关闭项；逐条取证在 git 历史 |
| `tech-debt.md` | 按 P1/P2/P3 编号的债务清单 + 已修留档 | 每条带证据、影响、建议、置信度 |

## 加一条

- 先判断落在哪一份：外部事实不可变 → limits；代码没做到 → gaps；能做到但质量欠账 → debt。
- 修完把状态改「已修」并写提交/测试名，**不要删行**；新债先加行再决定排期。
- `known-gaps.md` 体积大且不随版本走，在路径与版本守卫里显式跳过。

## 不变量

- 不把缺口写成承诺：`docs/contracts/` 里不出现「将来会支持」。
- 不把路线图混进 gaps：排期讨论不属于本区。
