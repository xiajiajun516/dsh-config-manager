# 第三方插件数据目录声明（`dsh.dataDirs`）v1

> 状态：**本仓实现并已落地的约定**（2026-10-14）。它是「让别的插件也能被配置管理器迁移」的钩子：
> 插件在自己的 `package.json` 里声明数据目录，配置管理器的「第三方插件数据」分区自动识别。

## 1. 为什么需要它

DSH 的配置有三个权威存储（`settings.yaml`、`cordis.patch.yml`、profile 目录），但**插件自己的数据目录没有统一约定**：
现实里散落在 `~/.dsh-<name>/`、`~/.<name>/`、`~/.dsh/<name>/` 三种形态，位置只有插件自己知道。
配置管理器因此把「已知插件」写成内置来源表（`src/core/plugin-data-registry.ts`），并为**未知插件**提供本条声明通道。

## 2. 声明位置与形状

声明写在插件包根目录的 `package.json` 的 `dsh` 字段下（与 `dsh.bundle` / `dsh.client` 同级）：

```json
{
  "name": "dsh-my-plugin",
  "dsh": {
    "dataDirs": [
      { "path": ".my-plugin", "role": "config", "env": ["MY_PLUGIN_DATA_DIR"], "exclude": ["cache", "bin"] },
      { "path": ".my-plugin/uploads", "role": "assets", "env": ["MY_PLUGIN_DATA_DIR", "MY_PLUGIN_UPLOAD_DIR"] }
    ]
  }
}
```

### 字段

| 字段 | 必填 | 含义 |
|---|---|---|
| `path` | 是 | **系统主目录（`~`）相对 POSIX 路径**（文件或目录）。必须以 `.` 之类相对路径开头：绝对路径、盘符路径（`C:/…`）、含 `..` 或空段的值一律让**整条声明作废**（不猜） |
| `role` | 否 | `"config"`（缺省）＝配置与轻量状态 → 进 `pluginData` 分区；`"assets"` ＝大体积用户数据 → 进 `pluginAssets` 分区；`"cache"` ＝可再生产物，**两个分区都不进**，只在调研信息里出现 |
| `env` | 否 | 会**整体搬走**该区域的环境变量名（字符串数组）。任一存在且取值与默认位置不同 → 该区域**跳过并报码**，绝不按默认位置读 |
| `exclude` | 否 | 仅目录区域：永不收集的**区域相对**子路径（如 `cache`），防止把可再生产物打进备份 |

## 2.1 根是**系统主目录**，不是 DSH 的配置目录

`path` 相对的是**系统主目录**（Windows = `%USERPROFILE%`，macOS/Linux = `$HOME`），因为这类数据的事实位置就在那里
（`~/.dsh-wallpaper-engine/`、`~/.mnemon/` …），而 DSH 的配置根是 `$DSH_HOME`（通常是 `~/.dsh`）—— **两者是不同的根**。

配置管理器为这两个分区单独接了一扇**以系统主目录为根**的文件门面；宿主没提供它（旧版本宿主）时，
两个分区**什么都不读、什么都不写**，并在导出告警/导入计划里如实说明原因（绝不退回 `$DSH_HOME` 去读一个不存在的路径，
那会把「放在别处」伪装成「没有数据」）。

## 3. 语义与保证

- **单元 = 区域**：每个区域在导出选择器里是一个可单独勾选的单元（id = `<分区>:<path>`），可以看到文件数与体积。
- **默认不勾选**：两个分区都属 `defaultIncluded = false`；用户显式勾选且按区域选择。
- **缓存永不收录**：`role: "cache"` 与 `exclude` 命中的内容不进包 —— 备份不是缓存转储。
- **读取口径**：只读**当前 profile 实际安装**的那份 `package.json`（`profiles/<profile>/node_modules/<pkg>/package.json`）；未安装 = 无声明，不会去别处找。
- **写侧白名单**：导入时只有「内置来源的区域」与「本机已安装插件声明的区域」下的路径允许写；包里的路径本身**不构成授权**（恶意包不能借此写到 home 的其他位置）。白名单之外的一律在计划里判 Error、执行期零写入。
- **安全边界（如实写明）**：这两个分区是本仓库唯一会写 `$DSH_HOME` **之外**的分区。边界由两层构成：
  ① 门面本身被限制在**系统主目录**之内（越界即抛）；② 只有注册表里已取证的区域与**本机已安装插件**声明的区域才在允许列表内。
  安装一个插件本就等于信任它能读写你的主目录；这条边界不改变该前提，只是不让**备份包**成为越权写入口。

## 4. 版本与兼容

- 数组缺省、字段不认识、形状非法 → **整条声明作废**（等价于没声明），绝不影响内置来源与其它声明。
- 该约定是**附加**信息：删掉 `dsh.dataDirs` 只等于「配置管理器不再自动识别该插件的数据」，不影响插件自身运行。
- 未来字段只做**追加**语义；已有字段的含义不改变。
