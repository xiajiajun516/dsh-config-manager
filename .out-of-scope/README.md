# `.out-of-scope/` — 被拒功能请求的概念档案

一个概念一份 kebab-case 文件，例如 `dark-mode.md`、`plugin-system.md`。**不是每条 issue 一份**：同一诉求的多条 issue 归到一个文件。

## 为什么存在

1. **机构记忆**：为什么拒过，关掉 issue 之后理由也不会丢。
2. **去重**：下一条同类请求进来时先读这里，直接指出旧决定，而不是重新吵一遍。

## 什么时候写

只在**功能请求（enhancement）被判不修**时写。三类 `wontfix` 里只有它是归档对象：

| 关闭原因 | 写 `.out-of-scope/`？ | 关闭时说什么 |
|---|---|---|
| 已实现 | **不写** | 指出代码位置 / 用法 |
| bug 不修 | **不写** | 写为什么不修 |
| 功能请求不修 | **写** | 引用本目录文件路径 |

## 文件格式

写法像一页短设计文档，不像数据库记录：

```markdown
# 单一主题

一句话结论：这个项目不做 X。

## Why this is out of scope

理由要具体 —— 项目定位、技术约束、或当初选了另一条路的取舍。不要写「最近没空」这类临时理由：那是延期，不是拒绝。

## Prior requests

- #42: "Add X"
- #87: "X for accessibility"
```

## 流程

1. 维护者判定不修；
2. 先查是否已有同概念文件 —— 有就追加到 `## Prior requests`，没有就新建；
3. 在 issue 里发评论说明决定并给出文件路径（首行带 AI 免责声明）；
4. 打 `wontfix` 再关闭。

## 改变主意时

删掉对应文件即可；旧 issue 是历史记录，不用重开；触发重议的新 issue 走正常 triage。
