# DSH Config Manager — 远程同步「自动同步」设计决策

> 文档性质：**设计决策文档（上游依据）**
> 下游实现规格：`docs/sync-redesign-spec.md`（方案 A）。本文只在**决策层面**回答三个问题：
> **① 自动同步做双向还是单向上传？② 什么时候触发？③ 冲突怎么处理（不弹窗）？**
> 不写 API 契约、不写调度器代码、不写历史 schema——这些已在 `sync-redesign-spec.md` 落实。
> 读者：产品负责人、m-engineer / m-client / reviewer；实现时以 `sync-redesign-spec.md` 为契约。

## 0. 结论先行

| 决策点 | 结论 | 一句话理由 |
|---|---|---|
| 方向 | **双向自动同步**（pull 合并 + push 上传），**不改成纯自动上传** | 纯上传会丢失「多台设备交替改同一份配置」的核心场景；双向才是配置一致性的正解 |
| 触发 | 双向两个方向各有触发时机：**上传**在「本地配置保存」时事件驱动；**下载**在「检测到远端新快照」时拉取 | 只在真有变化时动作，无空转、无混淆 |
| 冲突 | **自动同步遇冲突不弹窗、不静默覆盖**：跳过冲突项 + 保留双份可事后合并，只在「无冲突且无需人工干预」时才自动写本地 | 把「决策」从同步瞬间推迟到用户方便时——既不打断、也不丢数据 |
| 现状（方案 A）| 与本文一致：双向、无冲突才自动、冲突跳过记历史 | 本文为这些选择补上「为什么」 |

## 1. 现状与本问题的由来

现有 `sync-redesign-spec.md` §2.2 已明确了自动同步的设计：总开关、统一间隔、启动触发下载合并、双向 pull+push、遇冲突跳过并记历史、连续失败 3 次通知。但它**没有正面论证方向取舍**——默认写了「双向」，却没回答「为什么不是单向上传」。

这正是用户在评估时最容易被绕进去的地方：
- **静默覆盖**：如果自动同步是静默的，会不会偷偷覆盖用户配置？
- **弹窗选择**：如果遇冲突弹窗，岂不是又变回手动了，「自动」名存实亡？
- **要不要干脆改成纯自动上传**，只把本地变化推上去，回避冲突？

本文把这三个疑点一次说透。

---

## 2. 决策点一：方向 —— 双向，不是纯自动上传

### 2.1 为什么不能靠「静默覆盖」实现自动

「自动」意味着确定性：同一输入得到同一结果。如果结果是「覆盖」，那有两种退化：

- **总是覆盖本地** → 换台机器改配置会被没头没脑地冲掉，数据丢失不可接受；
- **覆盖前总问用户** → 每次同步都要人点头，等于把「自动」装进手动同步的壳里。

两个极端都站不住。所以**自动同步的前提是：保证不丢东西**——冲突必须被机制结构性消化掉，而不是靠用户在场。这正是「遇冲突跳过 + 保留双份」的由来（见 §4）。

### 2.2 为什么是双向而不是纯上传

「纯自动上传（本地 → 远端）」会失去本工具最核心的使用场景：**你在 A 机上改了配置，B 机下次打开应该拿到它**。单向上传解决不了「远端有更新、本地要拉」这件事，只能退化成手动拉取。

反之「双向」天然覆盖两种真实需求：

| 场景 | 方向 | 双向是否覆盖 |
|---|---|---|
| 本机改了配置，想同步到其它设备 | 上传（push） | ✅ |
| 另一台设备改了配置，本机要跟进 | 下载（pull 合并） | ✅ |
| 两台设备先后改了同一处 | 冲突，跳过 + 双份 | ✅ |

单向只覆盖第一行。所以**双向是「配置一致性」的完整解，单向只是它的子集**。这也与方案 A 已定的 `direction: 'pull' | 'push' | 'both'` 一致。

### 2.3 结论

保持双向自动同步。不改成纯自动上传。

> 附带结论：总开关同时控制上传+下载（方案 A 已定），避免「只开上传、忘了下载」导致多设备配置漂移的半自动状态——**要么全自动一致，要么手动**，不给用户留一个容易制造漂移的中间态。

## 3. 决策点二：触发时机 —— 事件驱动 + 轮询，两个方向各自触发

早期的一个困惑是「自动同步什么时候跑」。答案不是单一的定时器，而是**按方向区分触发时机**：

### 3.1 上传：本地保存时事件驱动（不是远程快照）

- 你在本机**编辑并保存了一个配置文件**（`settings` / `ui` / `providers` / `prompts` / `skills` / `agentPresets` 任一 portable 分区变动）→ 触发一次**上传**。
- 价值：**不做无意义的同步**。只有真改了才推，避免定时全量扫描的空转、卡顿和「什么都没改却同步半天」的迷惑。
- 需要节流/防抖：连续保存多次（比如设置面板里一顿操作）应合并成一次上传，避免对 git 工作副本的频繁 commit/push。

### 3.2 下载：检测到远端新快照时拉取

- **周期性/启动时检查**远端（git 仓库）是否出现比本地祖先（`sync-state.lastSnapshotId`）更新的快照；有 → 才触发下载合并。
- 价值：方向相反、时机不同——上传看「本地改了没」，下载看「远端多了没」。

### 3.3 与方案 A 的关系

方案 A 用**统一间隔定时器 + 启动触发**实现「周期性」这半边，用「push 侧由 exporter 现场导出 + diff 祖先」实现「有变化才动」的这半边。本文在此补一句**设计意图**：触发应尽量「看变化，不看时间」——时间只作为兜底轮询，真正驱动是「本地保存」与「远端新快照」两个事件。

> 触发时机汇总：

| 触发事件 | 方向 | 触发物 |
|---|---|---|
| 本地配置文件被保存（防抖合并） | 上传 | 本地改动 |
| 间隔到点 / DSH 启动 | 下载合并 | 远端新快照（无新生则不拉） |

## 4. 决策点三：冲突 —— 不弹窗、不覆盖，推迟决策

### 4.1 核心矛盾重述

- 自动同步想「无感」，而冲突决策天然需要「人在场」。
- 一旦弹窗，便捷性归零；一旦静默覆盖，安全性归零。

### 4.2 解法：把「选择」从同步瞬间移到事后

自动同步的冲突策略分两类：

1. **无冲突项**：`useRemote` / `keepLocal` / 自动合并 → 直接写本地（真·自动）。
2. **冲突项 / 需人工项**（`Conflict` / `MissingSecret` / `MissingDependency` / `Install` / `Error` / `PathMapping`）→ **不做任何写入**，跳过该项，并在同步历史标记 `skipped + conflictedSections`。**数据永不丢**，用户之后有闲再处理。

这拆掉了两难：

- **不弹窗** → 同步过程不打断用户，保持无感；
- **不覆盖** → 冲突项根本不写，不存在被偷偷冲掉的风险；
- **事后可处理** → 冲突以「同步历史里的 skipped 记录 + 双份保留」的形式留给人，用户方便时再合并。

「自动」的定义因此是：**自动处理所有能安全自动的部分；不能安全自动的部分，留下待办而非弹窗打断。** 这才是自动同步该有的样子——把便捷性留给无冲突的日常，把正确性交给机制，把少数决策推迟到人方便的时刻。

### 4.3 双份保留（可选增强，非本版必须）

`sync-redesign-spec.md` 采用「冲突跳过 + 不写本地」。若要更进一步防「远端值因此看不到」，可在冲突跳过时把远端值保留为一份不占位文件（如 `xxx.remote`）供事后对比——但这是**增强**，不是本版必需；冲突详情已在手动一键同步的 `SyncConflictDetail` 里完整呈现，自动同步只负责「安全地不写 + 记录」。

### 4.4 结论对应方案 A

方案 A §2.2/§6.3 已实现「无冲突才自动 + 冲突跳过记历史 + 连续失败 3 次通知」——与本文一致。本文为其补上**为什么**：这是「不弹窗 + 不丢数据」的唯一同时满足路径。

## 5. 决策点四（澄清）：自动同步 vs 一键同步的分工

很多困惑来自两者边界不清。明确分工：

| | 一键同步（手动） | 自动同步（后台） |
|---|---|---|
| 触发 | 用户点按钮 | 保存事件 / 轮询 |
| 差异确认 | **逐项确认**（默认采用远端可取消，冲突内联三选一） | **无确认**（无冲突才写） |
| 冲突 | 弹窗内联解决 | 跳过 + 记历史 |
| 决策权 | 用户全程在场 | 机制兜底，宁可跳过不写 |

两者共用同一套 preview / apply 底层，只是**决策权不同**：一键同步把决策交给人，自动同步把「可安全自动化部分」交给机制。没有谁是另一种的替代品——一键同步负责「我要看着办」，自动同步负责「日常无感一致」。

---

## 6. 对本设计的一个必要提醒（安全不变量）

- 自动同步只在 `portable` 分区（settings/ui/providers/plugins/prompts/skills/agentPresets）双向；凭据/会话/插件二进制等**永不自动上传**——自动 ≠ 放开所有数据。
- 远端快照 `containsSecrets=true` → 自动同步拒绝，与手动同规则。
- token 只存 DSH credentials，永不进 repoUrl/commit/日志/浏览器。
- 这些沿用 `sync-redesign-spec.md` 附录 B，自动同步不放松任何一条。
